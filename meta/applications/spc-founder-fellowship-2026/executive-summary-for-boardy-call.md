## Proposed core story

> **AI-native teams accumulate direction debt.**

As contexts and agents change, humans repeatedly reconstruct purpose, trade-offs,
evidence, and authority. Aimparency is repository-owned intent infrastructure:
replaceable agents can recover a durable contribution graph, choose and verify
bounded work, and revise shared priorities while human decisions remain explicit.
The smallest promise is: **change the executor without losing the project's
direction.**

The strongest candidate founder origin is a lived transition captured in Felix's
earlier first-person material: “I used to write loads of code. These days, AI
writes the code.” His scarce work moved from producing implementation toward
choosing, preserving rationale, and judging whether machine output serves the
larger purpose. This is compelling only if Felix confirms it as actual causality,
not a retrospective story.

The most credible present-tense wedge is **AI-native software teams coordinating
long-running or multiple coding agents**. Prompts and chats lose rationale; task
boards flatten contribution structure; Git records what changed but not why it
mattered; human decisions surface late; changing models risks changing
institutional memory.

The earned expansion is a **model-independent strategy layer for replaceable
specialist agents**. A constitutional layer for increasingly autonomous
organizations is mission-consistent, but it currently outruns both enforcement
and market evidence and should not lead this application.

Current adjacent tools make the bar high. Agent memories already preserve
instructions and learned facts; orchestration frameworks persist execution and
support human interrupts; project systems combine hierarchy, history, and agent
delegation. Aimparency's proposed distinct object is direction across those
systems: contribution to competing purposes, priority, evidence-driven revision,
and authority. This is a hypothesis to test against memory plus issues—not a
moat to assert.

## Strongest rejection case

A skeptical reviewer may see an intellectually rich personal ontology with too
many layers—developer tool, strategy agent, autonomous organization—and no
customer. The recursive application may look clever but prove little beyond
competent agent use. Existing platforms may absorb planning and memory features.

The response should not be a larger vision. It should be:

1. one concrete painful event;
2. one first buyer;
3. one product invariant that must remain independent of the executing model;

## Recommended eight-week default

Boardy should attack and improve this, not merely approve it:

1. Observe a recent consequential handoff failure in ten qualified AI-native
   teams before installing anything.
2. In three repositories, run comparable fresh-session handoffs against the
   team's strongest baseline: repository instructions, issues, Git, and ordinary
   agent memory.
3. Measure human restatement time, time to directionally correct action,
   wrong-direction rework, late human gates, and graph-maintenance cost.
4. Ask for payment only after preventing or shortening an observed failure.
5. Integrate, narrow, or reject the wedge if the baseline performs as well,
   teams will not maintain the graph, or nobody pays.
