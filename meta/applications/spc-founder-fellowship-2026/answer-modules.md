## Problem

> AI is making competent execution abundant, but long-running projects
> accumulate direction debt: humans repeatedly reconstruct what matters, why it
> matters, which trade-offs were already made, and which decisions still belong
> to them as contexts and agents change. Chats compress rationale, task trackers
> flatten it, and model-specific memory disappears when the executor changes.
> Better agents make this more consequential: they can travel farther in the
> wrong direction before anyone notices.

## Product

> Aimparency is repository-owned intent infrastructure. It represents work as a
> contribution graph, so a local action inherits the missions it serves. The
> graph stores priorities, phases, evidence, reflection, and explicit human
> gates. Replaceable agents can recover that state, choose bounded work, verify
> outcomes, and revise the shared plan without becoming the source of authority.
> The smallest promise is: change the executor without losing the project's
> direction.

## First user and wedge

> We start with technical founders and small AI-native software teams repeatedly
> using coding agents in one consequential repository. The painful moment is a
> resumed session or agent handoff where the founder must reconstruct project
> direction, a human decision surfaces late, or an agent completes locally
> sensible work for an obsolete objective. Aimparency wins only if it reduces
> that reconstruction and rework enough to outweigh the ceremony of maintaining
> the graph.

## Why existing tools do not make this redundant

> Agent memory preserves facts and instructions; orchestrators preserve execution
> state; project tools preserve planned work. Aimparency attempts to preserve the
> direction those systems serve: how local work contributes to competing
> purposes, which decisions remain human, and what evidence should change
> priority. The distinction is a hypothesis, not a moat. I will test it against
> memory-plus-issues as the baseline and integrate or reject the product if it
> does not reduce restatement and wrong-direction work.

## Why now

> Execution is becoming abundant and replaceable; human capacity to restate,
> supervise, and legitimize direction is not. Model improvements therefore do
> not remove this problem. They increase the cost of unclear authority because a
> capable agent can do more consequential work before a mistaken objective is
> noticed. The missing infrastructure is not another executor, but continuity of
> purpose across executors.

## Why SPC

> SPC is unusually aligned with the question behind Aimparency: when AI makes it
> possible to build almost anything quickly, how do you avoid building the wrong
> thing faster? I have made that question operational inside one project; I have
> not yet proved the first external market or final company shape. I want strong
> technical builders to expose direction failures in their own work, attack the
> product, and help determine whether this is a useful tool, a venture-scale
> strategy layer, or a thesis I should reject.

## What exists

> Aimparency is working open-source software, not a slide deck. It stores graph
> state beside a repository and provides a visual interface, model-neutral MCP
> tools, phases, value/cost-informed priorities, semantic retrieval, structured
> reflection, explicit human-dependent states, and aim-linked Git evidence.
> Codex, Claude, Gemini, Grok, and other wrapped executors can operate through the
> same graph; adapter existence does not imply equal production reliability.

## Narrow proof

> This application is a live continuity test. After session and context changes,
> Codex recovered the objective, deadline, mission paths, verified work, and
> unresolved human decisions from project state. The run exposed a real defect:
> human-dependent descendants were hidden from a phase priority view. Codex
> implemented and tested transitive, cycle-safe visibility under the same aim.
> This proves useful continuity inside one project—not demand, general alignment,
> or autonomous organizations.

## Eight-week learning plan

> I would first observe ten AI-native teams' real handoff failures, then run paired
> handoffs in three repositories: their best repository instructions, issues,
> Git, and agent memory versus the same setup plus Aimparency. I would measure
> human restatement time, time to a directionally correct action, wrong-direction
> rework, late human gates, and graph-maintenance cost. I would seek payment only
> after preventing a real failure. If the baseline performs as well, teams will
> not maintain the graph, or nobody pays, I will integrate, narrow, or reject it.

## Company path

> First, reduce direction reconstruction and wrong-direction work in AI-native
> repositories. If teams retain the graph across model changes, Aimparency can
> become the stable strategy layer above changing specialist agents. Only if the
> same trusted intent-and-evidence state generalizes should it expand into
> organizational workflows where authority and human relationships must remain
> explicit. The later steps are conditional on evidence, not three products I am
> claiming to have built.

## Moat hypothesis

> The moat is not graph data structures or an agent wrapper. It is trusted,
> accumulated intent-and-evidence state and the workflow by which humans and
> multiple executors keep that state authoritative. This is still a hypothesis.
> It becomes credible only when external teams retain the graph across model
> changes and permit it to guide consequential work.
